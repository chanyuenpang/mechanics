# 路由质量验证

`scripts/routing-quality.mjs` 只读载入项目，通过正式打开、限定投影和图计算入口验证路由。它不启动服务器，不保存机制或视图，不写 canonical 文件。真实游戏样本通过参数提供，独立工具不内置宿主项目路径或资料。

```sh
node scripts/routing-quality.mjs --project <项目目录> --view <视图ID> --output .claw/artifacts/routing-quality
node scripts/routing-quality.mjs --project <项目目录> --mechanic <机制ID> --output .claw/artifacts/routing-quality
node scripts/routing-quality.mjs --synthetic --output .claw/artifacts/routing-quality
node scripts/routing-quality.mjs --snapshot <历史报告JSON> --output <另一报告目录>
```

默认分别执行固定节点路由与完整 ELK 排版；可用 `--mode route` 或 `--mode layout` 单独执行。每次计算运行在独立 Worker，60 秒未完成时硬取消并报告失败。正式图存在限定投影节点却缺少已保存坐标时，验证明确失败，不臆造一份不同的测试布局。

输出包括 JSON 几何快照与可缩放查看的 HTML 对照页。上图是文件内有效的已保存路线缓存，下图是本次计算。缓存缺失时不提供虚构的基线。初始 ELK 算法失败的情况必须单独记录，不能拿保存位置重算成功替代完整自动排版成功。

项目文件可能同时被编辑器更新。跨版本比较应通过 `--snapshot` 固定第一次读取的 `sample`，不要在两次测试之间重新读盘并把不同布局当成同一基线。

路由缓存的几何签名包含算法版本。修改会影响最终路径的算法时，应同步递增 `src/web/route-cache.mjs` 的 `ROUTE_CACHE_VERSION`，否则节点坐标与拓扑未变时仍会复用旧路线。旧版本缓存按未命中处理，打开时固定节点重算并保存新快照；首次加载页面也必须进入同一打开流程。

本地更新验收还应刷新真实编辑器，确认旧缓存完成重算并保存，再次刷新直接恢复新路线。仅运行离线几何检查无法证明用户页面已加载新版代码。

## 指标与边界

- `hardInvalid`、`collinearOverlap` 与严格审计决定路线能否提交。
- `crossings` 是当前几何谓词统计的交叉事件数，包含拐点接触，不等于有交叉的边对数量。
- `endpointExcursions` 表示端点包围的几何指标，必要绕障不因该指标非零而被拒绝。
- `detour` 是超过端点曼哈顿距离的分档成本；`totalBends`、`maxBends` 与 `length` 分别记录总拐点、最大拐点和总长度。
- `nearParallel` 按近距平行线段的重叠长度与间距缺口累计，是比较用的拥挤成本，不是告警条数。
- 严格审计通过不等于没有交叉或近距；报告必须保留残余质量指标。不同节点布局之间也不能仅比较一个指标来宣称全面改善。

后处理以既有求解结果为起点，逐项保护节点避让、共线重叠、端点包围、交叉和折返绕路，再按同一质量向量接受改进。相邻端口的联合候选可在隔离状态中暂时变差，但只有最终整体改善才提交。搜索范围和轮数有上限，不承诺全局最优。

## 回归入口

```sh
node --test --test-concurrency=1 tests/routing-postprocess.test.mjs tests/layout.test.mjs tests/selection.test.mjs tests/recruitment-layout-regression.test.mjs tests/route-cache.test.mjs tests/routing-performance.test.mjs
npm run check
```

人工压力图包含 108 个节点、248 条边，混合网格、跨层连接、反馈环和枢纽端口竞争。实际复杂图仍须另行验证；人工样本不能替代用户指定的机制与视图。

性能用例共享同一台机器的 CPU，`npm run check` 串行运行测试，避免其他测试进程争用资源造成耗时误报。路由入口最多交替优化 16 轮，找到不再改善的结果便提前结束；回归同时覆盖完整排版后重建路线的一致性。

## 设计参考

ELK Layered 将分层、层内交叉优化和几何坐标计算分阶段执行，并支持正交路径与端口约束。当前工具只消费其节点位置，最终连线由自己的求解器生成，因此只调 ELK 的连线参数无法直接修复最终路径。[ELK 官方说明](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)

libavoid 会将受障碍变化影响、或可能获得更短路径的连线标记为需要重算；yFiles 提供按需重算整条线或局部线段、以及多个端口候选的能力。这些资料支持针对问题局部迭代的设计方向。本次实现复用现有候选与增量评分，没有引入新路由依赖。[libavoid Router](https://www.adaptagrams.org/documentation/classAvoid_1_1Router.html)、[yFiles Edge Routing](https://docs.yworks.com/yfiles-html/dguide/polyline_router/)
