# 游戏规则分析工具需求与范围

状态：2026-08-31 首次工程设计。方法论和产品目标来自需求讨论；文件结构、技术选型和分期是本轮设计决策，不是对既有产品的描述。

## 产品目标

为游戏设计者提供浏览器中的因果规则图工作台。将规则抽象为概念和促进/抑制关系，在不同颗粒度以及基础规则、关卡、敌人、手牌等组合范围内分析作用路径和设计疑点。分析对象是抽象规则，不是实时战局；关卡和手牌图表示纳入分析的规则组合，不承载当局血量、体力、目标实例或行动进度。

工具面向多种游戏，不能依赖任何宿主的规则实现、资产格式、游戏引擎或编辑器。工具源码独立管理；设计者编辑的节点定义图和分析文件保留在所分析游戏的项目目录，由该项目版本管理。

## 已明确的方法论

1. 节点表达概念；输入侧和输出侧都允许零条、一条或多条关系。
2. 连线方向为影响方向。正向表示源概念增多、增强或更可能发生时，目标也沿定义的方向增加；负向则抑制目标。正负不等于玩家视角的好坏。
3. 节点需要说明自身含义和变化方向。例如“敌人伤害”应明确为敌人造成的伤害，而不是敌人受到的伤害。共享“近战”概念正是接合机制的方式：敌人产出近战，某规则抑制近战，就能建立抽象抑制关系，不必核对某一局行动是否可执行。
4. 在适用条件一致的单条路径上，符号相乘可以解释间接影响；不计算胜率、影响强度或多条路径的净效果。
5. 单入单出的中间节点允许折叠成一条关系；折叠只改变视图，不删除源节点、来源、条件和中间步骤。重新展开应可恢复。
6. 折叠资格按当前组合网络判断，不能先把源图破坏性简化再叠加；自环、循环、分支和并行关系必须保留。
7. 孤立、只有输入没有输出、连接结构相似是设计疑点，不是自动判坏、合并或删除的理由。终点、资源消耗出口和未纳入当前分析范围的作用均需设计者判断。
8. 相似性比较只在相同范围和颗粒度下成立。费用、数值、时机、获得频率、条件等差异不能因为拓扑相似而丢失。

## 核心产品能力

| 能力 | 用户行为与结果 |
| --- | --- |
| 工作区 | 打开某个游戏的分析目录，不需要启动游戏 |
| 统一节点定义图 | 图形化浏览与维护共享节点 ID、名称、定义、变化方向及布局，查看被哪些分析图引用 |
| 分析图 | 新建、命名、编辑、保存独立文件；添加已有节点的引用与正负关系 |
| 组合浏览 | 同时启用任意多张分析图，公共概念按 ID 接合，保留每条关系的来源 |
| 编辑归属 | 浏览组合时明确当前编辑图；修改只归属被选中的源文件，不将组合结果写回基础图 |
| 保存组合 | 保存启用的图 ID、折叠节点和组合布局，下次恢复相同观察范围 |
| 影响解释 | 查看从某节点到某结果的路径、逐段符号、累计符号和机制说明；共享概念可直接揭示抽象协同与反制 |
| 设计疑点 | 提示当前范围内的孤立、作用出口、结构相似、相反作用路径，并展示证据 |

“基础”“关卡”“手牌”是分析图的用途，不是不同的文件格式或强制继承层级。每个工作区有自己的统一定义图；不同游戏同名节点不会自动认定为同一概念。

## 页面与主要流程

- 左侧：工作区与分析图清单，显示开关、组合选择，以及完整编辑器中的当前编辑归属。
- 中间：统一定义图或当前叠加图，正负连线、缩放、节点选择、折叠/展开。
- 右侧：概念含义、变化方向、所在图、关系来源和有范围的分析解释。

完整编辑流程：打开工作区 → 在定义图创建或复用概念 → 新建分析图并引用节点 → 连线并注明符号/条件 → 保存当前源文件 → 叠加其他图 → 解释作用链和设计疑点。

节点定义变更与图编辑分离。重命名不改变 ID；删除被引用的节点必须阻止并列出引用者。组合浏览不能偷偷覆盖来源图的定义或关系。

## 本轮交付边界

本轮交付独立仓库、源码分层、JSON Schema、跨文件校验、图算法基础、只读网页、示例工作区、项目接入与后续设计文档。以真实文件读取和纯函数/HTTP 测试证明骨架能工作。

不把完整可视化编辑、文件写入、自动保存、复杂布局、实时协作、云发布、游戏运行时接入、自动抽取规则、数值平衡模拟、AI 自动判定可玩性包含在本轮完成态内。后续实现必须沿已写明的合同推进，而非通过静默覆盖、默认节点或浏览器缓存假装保存成功。
