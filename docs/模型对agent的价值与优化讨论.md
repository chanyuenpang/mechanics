# 模型对 agent 的价值与优化讨论

状态：2026-08-31 讨论稿，已按用户明确的“分析抽象规则，不分析具体战局”修订。JSON、共享定义与图叠加已确认；以下优化是建议，不是新增协议承诺。尚无对照结果证明 agent 的准确率或效率已经提高。

## 模型的直接价值

工具帮助 agent 检索机制、解释间接作用、比较规则、发现设计修改位置。它支持设计决策，而不是替玩家判断某一刻该出哪张牌。

例如：`敌人 +→ 近战`，`后撤步 +→ 远拒 −→ 近战`。agent 可以直接识别后撤步抑制该敌人产出的近战机制；这个结论不需要还原当局体力、敌人实例、目标距离或操作时机。共享近战概念是跨规则检索反制关系的接口，不是应当消除的抽象。

关卡叠加表示“这一关包含哪些规则与机制”。它能帮助分析机制压力和应对手段的覆盖，而非载入实时战斗快照。例如关卡同时引入近战与远程机制，后撤步只连接到近战，就能看出反制覆盖范围；不应由此夸大为它克制敌人的全部机制。

| agent 的任务 | 图能够直接提供什么 |
| --- | --- |
| 找协同与反制 | 共享作用对象、促进/抑制关系、间接路径 |
| 解释设计作用 | 从规则到设计目标的逐段链条与来源 |
| 比较卡牌与敌人 | 作用对象、输入出口、分支、代价与反馈的结构差异 |
| 分析关卡组合 | 引入了哪些机制，哪些有应对路径，哪些没有已建模的应对 |
| 提出修改建议 | 应补在哪个机制接口、资源出口或反制路径上；哪些节点值得讨论合并 |

## 四个贴合抽象层的优化

### 1. 节点定义与颗粒度明确

每个节点只表达一种稳定含义。“敌人伤害”应区分造成与受到；“手牌”应说明是手牌数量、质量还是牌种能力；“近战”是共享机制，不按某局敌人逐个复制。

颗粒度可以折叠/展开，结构相似性必须在同一颗粒度下比较。不要把综合概念“生存能力”与具体机制“护甲量”直接当成相同层级的等价节点。现有 `description` 和 `increaseMeaning` 先承担这一约束，不急于增加复杂类型系统。

### 2. 多路径比单链更有分析价值

同时显示同向通道、相反通道、共同作用对象、分支和反馈环，帮助发现协同与取舍。

假设例子：`换牌 +→ 抽牌 +→ 手牌数量`，同时 `换牌 +→ 弃牌 −→ 手牌数量`。agent 能判断换牌存在两条方向相反的作用通道，因此不能只看抽牌路径便把它归为纯手牌增长机制。

符号表达结构方向，不表示强度。不能数路径条数、正负抵消或仅凭环的符号得出净收益、稳定性和胜率。没有数值模型也不影响“存在协同/反制/取舍通道”这一结构判断。

### 3. 围绕设计目标组织查询

查询应服务于设计任务，例如“近战压力有哪些应对机制”“这个资源有哪些来源和用途”“这两张牌在哪些机制接口重复”。目标节点可由用户选择，不必硬编码所有路径最后都通向游戏失败。

图可以指出需要补充或改变的连接位置；设计者再决定具体内容、表现形式和数值。将来优先提供上游影响、下游影响、共同作用对象、图间差异与结构相似等少量确定性查询，而非把整张图反复塞给 agent。当前纯图函数是接口基础，但尚未实现 MCP 或专用 agent 查询服务。

### 4. 保留范围与推导依据

结论附带工作区/所选图、节点 ID 和 `(graphId, edgeId)`。来源图身份是追踪依据；还应在说明中区分正式定义的规则与设计假设，不需要先建立复杂置信度系统。

未找到反制路径应表述为“当前模型未记录”，不能断言任何其他规则都不可能反制。孤立、无输出和结构相似是讨论线索，不自动判坏、删除或合并。终点和刻意设计的资源消耗口可能合理。

## 建议的 agent 回答合同（待实现）

输入：所选图、问题、关注节点或设计目标、分析颗粒度。输出：结构结论、完整作用链、来源、相关的反向/代价通道、模型覆盖边界与候选修改位置。

例如：“后撤步通过远拒抑制近战，因此对产出近战的敌人构成机制反制；在这组图中没有连接到远程机制。依据为手牌图的两条边与敌人图的近战产出边。”这就是有用的设计分析结果，无需追加某局行动可执行性检查。

当前不引入实例绑定、当局体力检查、即时行动推荐、回合状态机、资源账本和规划搜索。此前将这些列为首要优化的建议已经撤回；它们解决另一类问题，不能成为抽象反制关系成立的前置条件。

## 怎样验证它对 agent 有帮助

用相同的抽象规则事实构造六类问题：共享概念反制链、间接协同、正负路径竞争、相似规则但作用范围不同、资源来源/出口缺口、基础规则与关卡叠加后的覆盖变化。固定 agent 模型、问题、预算和事实，对比纯文本与“纯文本＋图”，重复运行记录波动。

比较机制检索完整度、反制/协同方向是否正确、代价与相反通道是否遗漏、能否定位证据、是否把模型未覆盖误说成不存在，以及耗时、token 和维护图的人力成本。先以小案例检验方向，不把少量例子泛化为所有游戏的效果证明。
