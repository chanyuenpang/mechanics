# 开发路线与验收边界

## 当前切片：可验证框架

- 独立源码仓库、Schema 与三个文档类型，宿主通过子模块使用。
- 工作区必须显式提供；整体引用校验、未知版本拒绝、受限本地读取。
- 统一节点定义总览、分析图叠加、来源说明、路径查询、可逆折叠与范围内疑点。
- 当前网页只读；没有新建、编辑、拖拽连线或保存 API。没有发布云网站。
- 结构与 HTTP 行为通过 `npm run check` 验证；若没有浏览器实测，不把它称为完整交互验收。

## 下一切片：最小创建与保存

先实现安全文件服务，再接表单：节点定义维护 → 新建图 → 引用节点 → 编辑正负边 → 保存 → 重新读取。暂不要求高级拖拽。

验收必须证明：实际文件位于指定工作区；旧 revision 冲突、断引用、被引用定义删除、第二写入进程及原子替换失败均明确拒绝；提交后确认失败显示结果待确认。未登记的新文件不能悄悄纳入工作区。测试全部使用隔离临时目录，不写真实设计文件。

## 再下一切片：可视化编辑

在已验证保存合同上增加节点拖拽、正负连线创建、当前编辑图、布局保存、撤销与重做。允许查看多张图但只能明确地修改一个源文档；折叠摘要不可被误当成原始边编辑。删除与合并必须展示引用影响，不自动改造玩法。

## agent 优化试验

面向抽象规则设计，先以相同规则事实和固定问题对比纯文本与文本＋图：机制协同/反制检索、覆盖缺口、代价路径、结构相似、证据完整度、耗时和 token 成本。只要敌人产出近战，抑制近战的规则即可被识别为反制路径，不需要先核对具体战局条件。实时战斗策略、可执行条件、实例绑定与规划搜索不属于这一试验目标。

本轮拟议的优化见[模型对 agent 的价值与优化讨论](模型对agent的价值与优化讨论.md)，它们是待讨论项，不在当前协议中隐式生效。
