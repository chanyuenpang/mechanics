# 递归布局算法研究与原型验证

日期：2026-09-06。状态：递归基础布局、子树方向迭代与拖动局部路由已接入正式编辑器；下文区分基础实验与后续接入验证。

## 结论

用户提出的“把节点群视为带对外端口的大节点，端口顺序指导内部位置，内部空间需求再影响外部布局”，已经有非常接近的成熟实现：ELK Layered 的 hierarchical layer sweep。HOLA 补充了保持核心拓扑、移动核心给附属树腾空间的做法；OGDF 提供平面嵌入、分解与正交布局路线。

适合继续推进的方案是：**自动建立收缩树，让父子层协商端口和节点顺序，按内部真实尺寸安排空间，再逐轮展开或解除不利的分组约束。** 收缩树记录求解关系，最终布局可以跳过没有帮助的中间层。分组质量必须由展开后的完整连线评价确认。

基础求解器已提取为浏览器与实验脚本共用的纯 JavaScript 模块，使用 elkjs 作为子求解器。正式自动整理直接提交联合求解的节点、端口与路径，不再进入旧的全图路由结算。实验输入只读冻结；用户在编辑器执行整理和拖动时，按原有机制草稿/视图保存合同写入展示几何，不改变节点身份、关系与箭头语义。

## 正式接入与方向迭代

`src/web/hierarchical-layout.mjs` 保持用户认可的基础候选生成和接受顺序。`flow-refinement.mjs` 在它之后进行最多两轮改进，每轮优先检查回流子树：尝试原形、水平翻转，以及按真实箭头方向重排内部；再将子树整体放回父层。每轮最多检查 16 个组，仅重新连接组的边界边。

方向迭代要求回流边严格减少、交叉不增加、不产生穿节点或重叠，并限制全图总线长不超过基础结果的 115%。回流指标定义为目标节点横坐标小于源节点；另检查路径累计向左距离。它没有把同列边计为向右，也没有证明最少回流或全局最优。固定的候选预算可能保留仍可改善的结果。

下表是同一批冻结输入上的额外方向迭代，不与不同版本的实时游戏数据混比：

| 图 | 回流边 | 交叉数 | 总线长 | 额外迭代耗时 |
| --- | ---: | ---: | ---: | ---: |
| battle，22 节点/24 边 | 11 → 9 | 0 → 0 | 4442 → 4442 | 717 ms |
| 卡牌循环，12 节点/16 边 | 9 → 7 | 0 → 0 | 3857 → 3405 | 706 ms |
| s7，65 节点/133 边 | 55 → 55 | 39 → 39 | 45655 → 45655 | 432 ms |

这是本机单次测量，完整整理还需加上基础求解耗时。s7 未获得满足约束的额外改善，不能声称方向问题已经解决。先前卡牌循环 9 → 5 的候选会把总线长增加约 72%，已被拒绝。

`local-routing.mjs` 使用 `libavoid-js@0.5.0-beta.5` 提供的正交路由。拖动落点固定，只移动与落点直接碰撞的近邻；其余节点是静态障碍。只计算关联边、被新节点位置挡住的边和缺失路径，未受影响的路线对象原样保留，没有邻接扩散或全图回退。候选包括保留端口、面向目标的端口、接回原通道，以及共同投影区间内直接构造直线。只有受影响边的端口可以变化。

libavoid 的当前 JS 绑定没有暴露固定整条路线的接口，所以外围连线不注册为可优化 connector；接回旧通道与逐段平移候选直接读取外围固定路线的占用，最后按完整合并几何审计。初版仅将重叠纳入评分，后续修正为拒绝任何涉及局部路线的共线重叠，详见文末局部避障修复。两类端口候选均不可行时显式报错。早期单次拖动的六个冻结案例耗时约 2～157 ms，落点、外围节点、外围路线的精确不变断言均通过。该边界意味着局部空间完全不足时会失败，不会擅自移动远处节点。

Worker 单独允许编译随包提供的 WASM 及 Emscripten 动态函数包装，普通页面仍禁止动态脚本求值。仅开放 `wasm-unsafe-eval` 不足以运行这个版本的 JS 绑定，因此 `unsafe-eval` 只用于计算 Worker 的响应策略。新增浏览器依赖通过静态白名单提供，WASM 约 492 KB；不依赖宿主运行时。自动整理与选中子图整理共用新入口，页面与 Worker 不再加载 WebCola；历史分组对照保存在实验目录。旧画布路由辅助函数仍供历史回归测试使用，正式计算入口已不调用。

## 成熟实现中可以直接借鉴的部分

| 实现 | 已核实的具体机制 | 边界 |
| --- | --- | --- |
| ELK hierarchical layer sweep | 外层排入口端口，入口顺序影响内部节点；扫过子图后，内部出口顺序反馈到父层；反向扫描继续改善交叉 | 需要调用方提供分组，分层与端口侧向仍限制搜索空间 |
| ELK hierarchical resizing | 子图实际宽高回写父节点，再参与父层后续坐标和路由计算 | 尺寸回写不等于自动重启已经结束的交叉排序 |
| HOLA | 递归剥叶，先布核心和附属树；将树放入核心的面时，通过约束投影移动核心、腾出空间 | 主要处理通过树根附着的结构，未核实任意多接口组的递归协商 |
| OGDF multilevel | 收缩、粗层布局、逐层还原与细化 | 通用框架默认偏能量布局，不是现成的组端口合同 |
| OGDF planarization | 先处理嵌入与交叉，再生成正交形状和坐标；可以移除、重插边改善交叉 | 插边局部最优不等于全图最优；固定嵌入不是矩形四边的固定端口 |

ELK 的直接证据是 [LayerSweepCrossingMinimizer](https://github.com/eclipse-elk/elk/blob/master/plugins/org.eclipse.elk.alg.layered/src/org/eclipse/elk/alg/layered/p3order/LayerSweepCrossingMinimizer.java#L55)。类说明明确给出了父子双向定序流程，循环会比较交叉并保留改善结果。

端口顺序不宜过早固定：[LayerSweepTypeDecider](https://github.com/eclipse-elk/elk/blob/master/plugins/org.eclipse.elk.alg.layered/src/org/eclipse/elk/alg/layered/p3order/LayerSweepTypeDecider.java#L66) 对已经固定父节点端口顺序的子图选择 bottom-up。使用 ELK 的联合扫描时，应允许顺序变化；自己管理外循环时，才把某轮端口顺序作为对子问题的固定输入。

尺寸向上传播见 [HierarchicalNodeResizingProcessor](https://github.com/eclipse-elk/elk/blob/master/plugins/org.eclipse.elk.alg.layered/src/org/eclipse/elk/alg/layered/intermediate/HierarchicalNodeResizingProcessor.java#L79)。ELK 通用 topdown 引擎另有缩放子内容的机制，不能把它当作本需求的“保持节点尺寸并扩张空间”。

HOLA 的依据是 [主流程](https://github.com/mjwybrow/adaptagrams/blob/master/cola/libdialect/hola.cpp#L236) 与 [树放置和空间扩张](https://github.com/mjwybrow/adaptagrams/blob/master/cola/libdialect/treeplacement.cpp#L85)。OGDF 的依据是 [PlanarizationLayout](https://ogdf.github.io/doc/ogdf/classogdf_1_1_planarization_layout.html)、[BCTree](https://ogdf.github.io/doc/ogdf/classogdf_1_1_b_c_tree.html) 和 [ModularMultilevelMixer](https://ogdf.github.io/doc/ogdf/classogdf_1_1_modular_multilevel_mixer.html)。这些属于官方源码与文档研究，本轮没有编译运行 HOLA 或 OGDF。

## 原型算法

1. 建立不区分方向的邻接关系，用队列递归吸收只有一个外部邻居的节点；合并树保存原始身份。双向关系在邻居计数中算一个邻居，真实两条边均保留。
2. 在收缩结果上，用相邻组的正模块度增益建立候选组。每个组记录内部成员、真实跨组边、内部连接节点和方向。没有按机制文件归属合并，也没有硬编码样本分组。
3. 为几何求解选一个临时方向：从高度节点开始做无向广度遍历，按遍历顺序统一边朝向。语义方向仍保存在原边中，输出路线按原始 source → target 恢复。这样双向规则不必在几何上变成相互冲突的流向。
4. 向 ELK 提交当前分组层，启用 `INCLUDE_CHILDREN`、跨层扫描与双侧相邻交换。节点大小为 166 × 62；节点、端口、组大小和路线一起计算。
5. 每轮尝试把一个组展开成子组，或直接解除该组约束；重新计算完整几何，接受当轮最好的严格改善，最多三轮。所有尝试和接受记录都输出到报告。
6. 将逐层展开结果与同一求解方向下的不分组候选比较。两种结果都明确保留；计算失败会报错，不以其他候选掩盖失败。

评价优先级为：几何完整和合法、自交/节点冲突为零 → 交叉与接触数量 → 共线重叠长度 → 近距离平行线惩罚 → 转弯数 → 总线长。没有用缩短线长抵消新增交叉，也没有把十字交叉改成贴住的转弯后记作成功。

叶子收缩的实现使用邻接表、队列及合并树，为 O(V + E)。社区合并、候选求解和完整几何检查目前是研究实现，尚未增量化。端口局部排序可使用外部对应关系直接推导；不需要一开始枚举所有端口排列。

将临时几何方向与真实方向分离，也有成熟研究依据：[Layered Drawing of Undirected Graphs with Generalized Port Constraints](https://arxiv.org/abs/2008.10583)。该论文研究了有端口分组的无向图如何选择临时朝向；本文原型使用自己的简单广度遍历候选，没有复现论文全部算法或基准结果。

## 三个机制合同的实际验证

针对当前 elkjs 执行了最小小图测试，已确认：

- 交换外部源节点的端口顺序，会交换子组内两个节点的上下位置。
- 子组内部顺序改变后，外部目标节点的对应端口顺序随之改变。
- 把子组内一个节点从宽 166 改为 500，父组实际宽度增加，下游外部节点随之向右移动。

这验证的是同次联合布局中的传播。原型外循环重新求解整个候选，尚未实现独立子求解器之间的增量消息协商。

另一个直接指定 compound 边界 `FIXED_ORDER` 的小图没有获得预期顺序，根图直接使用外部端口的探针还触发了 ELK 异常。因此当前原型使用跨层真实边与可协商的组端口，没有把那个手工边界探针当作通过。将来实现显式接口合同，需要独立解决并测试这个路径。

## 下一步应补的算法能力

当前版本已替换正式计算入口，独立验证入口继续保留。后续仍可补三项：

1. **对简单结构直接构造布局。** 叶子、链与单根附属树采用直接模板或 HOLA 式树放置；结合桥、割点分解寻找真正的小核心。割点在不同块中只能有虚拟引用，最终仍显示一个真实节点。
2. **把平面嵌入作为核心候选。** 独立使用 NetworkX 3.6.1 检查：battle、STS 和 108 节点压力图的底层无向简单图均可平面绘制，s7 不可平面。前三者应追求零交叉；s7 应先压低核心交叉，再做正交形状和空间。嵌入顺序与矩形端口侧向要分别处理。依据见 [平面性检验合同](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.planarity.check_planarity.html)，结果保存了嵌入或不可平面证据，未声称得到 s7 最小交叉数。
3. **增加由冲突触发的局部移动。** 以交叉或拥挤位置定位相关节点、端口与组；只重排相关边界，沿通道切开空间并移动一侧节点。内部返回宽高及端口需求，变化向父层传播；跨组线和受移动影响的邻边一起评价。共同端点的可交换路线应直接解开，避免把可构造的操作变成大范围搜索。

每个组的接口至少需要：原始边 ID、真实内部端点、方向、边界侧向、沿边界的相对顺序，以及实际宽高。父层可以只处理接口，但不能丢掉这些映射或默认为任意端口顺序都适合内部。

## 局部改动的节点避障与共线重叠修复

原实现的直接连接没有登记到 libavoid，其它局部 connector 看不到它；接回旧路线的候选又只比较拐点和长度，完整合并的共线重叠仅用于评分。这些缺口分别修正为：登记直接连接、按与当前其它路线的实际关系选择旧通道、对冲突段进行最多四轮局部平移。端口只能沿原节点边界滑动，每步优先消除短接入段与重叠，再评价交叉、接触、间距、拐点与线长。单边评价不重复计算固定边之间的关系；最终仍使用独立的完整几何审计，拒绝穿节点、节点重叠、自交和任何涉及局部路线的共线重叠。外围既有重叠不触发全图修复。

## 局部刷新后的回字形剪枝

避障与最短段校验不能替代简化校验。上一版只在首尾不足 30px 时尝试一次转弯，普通局部路线主要检查整条拉直；接回原通道后，即使连续子路径可以缩短，也不会主动剪掉。另一个原因是平行间距评分早于转弯和长度：人工四节点复现中，原算法为避开一段相距 10px 的平行线，保留了六次转弯的回字形，实际上换当前边的一个端口就能一次转弯接通，且无新增交叉或重叠。

当前先完成 30px 接入和通道分离，再逐边尝试相邻侧端口的一次转弯，随后运行 `shortcutLocalRoutes`。剪枝枚举原路线的连续子路径，用直线或一次转弯替换，保留首尾端口，并明确检查朝外的法线；沿节点边框走不算合法接入。只接受折点更少、线长不增加、交叉与接触总数不增加、重叠不增加且通过节点与自交审计的候选。外围路线只读。每个接受操作都使总折点数下降，迭代到没有此类捷径为止，不采用任意次数后静默结束。

## 节点对共享通道

本轮要求同一对节点的关系始终共用一条规划路径，展开后相邻且有间隙；不能把关系数量减少视为质量改善的充分证据，合并后交叉不增加是四张冻结图的验收条件。

`edgeBundles` 按无向节点对分组，成员保留原始 ID、source、target 和 sign。正式自动整理只向 ELK 提交每组的一个代表连接，节点社区的关联度仍累计原始成员条数；所有水平朝向评价、子树候选和边界方向也逐条计算成员，避免代表边覆盖其他关系的方向。中心通道相交的估算代价乘以两组成员数，最终验收仍使用完整展开后的真实路线，估算不替代几何审计。

`routePairChannels` 统一规划中心路径，按稳定的成员顺序向两侧展开，间隔 12px。每个拐点取相邻两条偏移直线的交点；反向成员只反转自己的点序，不改变通道侧别。候选包含已有通道、直线、一次转弯与简单外绕路径，必要时以一个 connector 和整组半宽调用 libavoid。只有展开后无穿节点、自交、组内交叉、共线重叠，且所有接入段不少于 30px 的候选才能提交。中心子路径简化也必须整组通过。宽通道先占位，再做一轮以已有实际路线为上下文的改进；不保证任意图的全局最优。

局部刷新在计算前封闭同节点对的影响范围：任一成员失效会包含全组，未受影响的关系对象保持只读。删除中间成员后，几何一致性检查会识别旧空槽，重新收紧至 12px；已有通道完整时不重算。碰撞松弛仍限于落点的直接近邻，并补查落点四角，避免单轴候选都被占用时漏掉已有的对角空间。路线缓存版本从 2 升至 3，旧节点坐标保留，旧路线不再长期绕过新算法。

## 共享通道的重复计算优化

用户指出，合并连接本应减少计算量。分阶段实测证实初始布局已有收益：相同机器、相同图与配置下，原始 133 条关系约 3.43s，合成 97 条通道约 3.13s；自适应布局分别求解 44 次与 46 次。整体变慢来自新增方向调整与通道搜索中的重复工作，不能把该成本简单归因于关系数量。

保持几何结果不变的改动如下：

- 单节点子树的原形和镜像完全相同；形状及目标位置精确去重，仍保留最先出现的候选和既有择优规则。
- 局部单边候选先查看不变外围是否仍有硬错误；当前全图重叠已经为零时，再按该边对外的冲突贡献排除明确更差的候选。可能改善、短线修复及舍入边界继续做完整审计。
- 审计预建节点和边索引，按横坐标扫描线段外框，只对空间相邻的段对做精确检测。保留原来的段对累加顺序、EPS 和 12px 阈值，避免浮点舍入改变排序。
- 通道候选先比较乐观代价下界；同一次规划的障碍位置固定，相同宽度、节点及端口组合的 libavoid 结果跨两轮复用。缓存只属于本次调用，不跨拖动位置复用。
