# 游戏规则分析文件协议：工作区 v3、研究 v1/v2、定义与视图 v1

UTF-8 JSON 已由用户在 2026-08-31 确认。结构的唯一机器合同是 [`schemas/protocol.schema.json`](../schemas/protocol.schema.json)。工作区 v3 新增独立视图文件与最近打开引用；0.5.0 支持研究 v1/v2，定义与视图仍为 v1。旧 v1/v2 工作区 Schema 只供显式迁移器读取。

## 四类文档

| 文档 | 必填内容 | 唯一归属 |
| --- | --- | --- |
| `workspace.json` | `schemaVersion: 3`、`kind: "workspace"`、`id`、`name`、`definitions`、`compositions` | 工作区身份、唯一定义入口、历史组合与最近打开记录 |
| `definitions.graph.json` | `schemaVersion: 1`、`kind: "definitions"`、`workspaceId`、`nodes`、`positions` | 统一概念与默认布局 |
| `analyses/*.analysis.json` | `schemaVersion: 1` 或 `2`、`kind: "analysis"`、`workspaceId`、`id`、`name`、`scope`、`nodeIds`、`edges`、`positions` | 某张图的关系、范围和局部布局 |
| 任意普通目录的 `*.view.json` | `schemaVersion: 1`、`kind: "view"`、`workspaceId`、`id`、`name`、`graphIds`、`activeLayerId`、`collapsedNodeIds`、`positions` | 命名叠加选择，不拥有规则 |

所有路径相对于工作区根。递归发现普通 `*.analysis.json` 和 `*.view.json`，可在同一目录混放；排除隐藏条目和 node_modules，不持久化第二份清单。两类 ID 分别唯一，允许分析图与视图同 ID，路径映射按 `(kind,id)` 查找。支持中文路径，拒绝路径穿越、绝对路径、非法文件名、符号链接/junction 和嵌套工作区。未知版本、未知字段、坏文件、重复 ID、非法符号都整体拒绝。发现时点与迁移见 [CLI 与工作区](CLI与工作区.md)。

## 统一节点定义图

```json
{
  "id": "player-health",
  "label": "我方血量",
  "description": "当前分析主体的剩余血量，不指敌人血量。",
  "increaseMeaning": "剩余血量增加。",
  "tags": ["资源"]
}
```

`id` 在工作区内唯一，使用小写英文字母开头及英文字母、数字、点、横线或下划线，长度不超过 96。显示名可改；ID 不随名称改变。不同游戏默认拥有独立的定义图。`description` 说明抽象含义与粒度；`increaseMeaning` 给正负连线提供方向基准，不能空白。共享概念用于接合规则，不要求为每个敌人实例复制近战节点。

`positions` 是 `{ "节点ID": { "x": 40, "y": 80 } }`。未存布局的节点由页面计算临时摆放，不写回文件。定义图不拥有因果边；总览可将分析图的边投影在这些节点之间并显示来源。

## 分析图与关系

```json
{
  "id": "damage-reduces-health",
  "source": "enemy-damage",
  "target": "player-health",
  "sign": -1,
  "condition": "伤害已经命中且未被吸收。",
  "note": "这是敌人对我方造成的伤害，而不是敌人受到的伤害。"
}
```

节点必须先定义，再在分析图 `nodeIds` 中引用；边端点必须属于该图的 `nodeIds`。边 ID 只在所属图内唯一；完整来源键是 `(graphId, edgeId)`。`scope` 写明图的规则范围、颗粒度、假设和未覆盖范围。`condition` 与 `note` 必须存在，可以为空，作为机制说明；条件不是当前战局的可执行状态，不需要判定某局体力或时序才能查询抽象抑制关系。本协议不承担 AND、资源守恒、阈值、时序或概率计算。

`sign: 1` 表示促进，`sign: -1` 表示抑制。消耗应表达为行动对资源的负向作用；资源支持行动可以是另一条正向关系，两者不是同一种输入。

## 0.5.0 包含关系与研究 v2

v2 的每条作用边增加 `relation: "influence"`，保留 `sign: 1/-1`；包含边采用 `relation: "contains"`，禁止携带 sign。例如：

```json
{ "id": "play-contains-backstep", "source": "play", "target": "backstep", "relation": "contains", "condition": "", "note": "后撤步是手牌释放的一种" }
```

2026-09-01 用户修订：黄色等号双向传递宏观影响，可以位于路径开头、中间或末尾，不改变正负号。不建模“禁止”或具体效果。正负影响边仍仅沿 source → target；相反方向的正负边独立保存，不自动抵消。contains 保留原结构，其 source/target 仅记录两个端点，不限制遍历方向。旧 v2 文件中的等号按此新语义解释，不改写文件；不要混用旧版单向推理工具。纯等号链返回 `kind: "containment"`，没有 sign；有正负边的路径返回 `kind: "influence"` 和相乘后的 sign。反向等号步骤保留原 source/target、来源、前提，并添加只读 traversalSource/traversalTarget 表明本次遍历方向。查询使用未折叠原图，不写回派生边，不证明数值相同或实时生效。

包含允许闭环与多条独立来源，只拒绝连接自身。简单路径不重复访问节点，并设数量、深度上限；截断明确标记，不迭代累计效果。研究、视图、追踪与下游筛选使用同一双向规则，未选研究不参与计算。

v1 打开和普通正负/位置编辑保持 v1；内存投影明确标注 influence，不修改输入文件。新建研究为 v2。首次添加包含或把作用改为包含时，只升级当前草稿，并显示保存将升级提示；保存前撤销或放弃可以还原 v1。保存后不自动降级。工作区、定义、视图和其他研究不升级，旧工具明确拒绝研究 v2。

右键框选与多选只在页面存在，不进入协议。群组移动一次提交完整 positions：研究手动保存、视图自动保存；共同位移限制在坐标边界内，不能逐个裁剪破坏队形。取消手势不写入。包含相邻节点不能折叠；已有视图的折叠因包含边失效时仍走显式展开修复。

## 视图、最近打开与折叠

已有命名组合存于 `workspace.json` 的 `compositions`，包含 `id`、`name`、`graphIds`、`collapsedNodeIds`、`positions`。它只保存观察选择和布局，不复制节点或原始边。0.2.1 移除命名组合的界面入口，保留字段、原有内容和校验；不需要迁移文件。

独立视图示例（文件名、目录与 ID 相互独立）：

```json
{
  "schemaVersion": 1,
  "kind": "view",
  "workspaceId": "sample-card-game",
  "id": "melee-response",
  "name": "近战反制",
  "graphIds": ["basic-rules", "encounter", "hand"],
  "activeLayerId": null,
  "collapsedNodeIds": [],
  "positions": {}
}
```

`graphIds` 只允许分析图 ID；不嵌套视图。`activeLayerId` 结构仍允许可见分析图 ID 或 `null`，用于读取 0.3.0 文件；0.4.0 视图源规则只读，新建和展示编辑一律写 `null`。旧非空字段用于在内存恢复原画面，不在打开时改文件；首次编辑展示才物化位置并置空。折叠与位置 ID 必须属于所选图中的节点。未打开的视图也参与全工作区校验，缺失来源不能部分加载。

可选 `workspace.lastView` 有两种互斥形式：内联状态与 `{ "viewId": "melee-response" }`，命名引用不能附带第二份勾选快照。0.4.0 打开研究只记录 `{ "graphIds": ["hand"], "activeLayerId": "hand", "collapsedNodeIds": [], "positions": {} }`；旧多图或带展示状态的内联记录只读预览，须明确保存为视图或放弃，不在启动时改写。无记录首次打开第一张研究。打开视图总是读取最新源图，重复点击也重新读取；候选验证成功后才替换画面。顶部概念表/分析图切换保留上下文，不写最近记录。

用户在 2026-08-31 确认采用双模式：研究只看和编辑自身；只有命名视图提供勾选。视图成员、组合位置、折叠自动写回 `.view.json`，源规则只读。「新建视图」从空组合开始，也可从当前研究创建或将视图另存为。点研究离开视图不改原视图；返回视图重新读取源规则。创建文件与写最近记录是两次独立提交，后一步失败明确报告已创建路径，不重复创建或删除文件。

- 按稳定 ID 接合节点；同名异 ID 不自动合并。
- 同一图重复选择只算一次；图顺序不决定覆盖权。
- 不同图的同向或异向边都保留，来源可展开；不把异号边算成零。
- `graphIds` 是当前模型范围，不等于当前回合已经激活的行动集合。
- 折叠在完整选图结果上执行。单入单出且不在有向环中的节点才允许折叠；摘要保留全部原始边与中间节点，重建未折叠投影即可展开。无效折叠请求报错。
- 研究位置优先于共享默认布局；视图使用自己的 `positions`，没有位置时用共享默认布局或按定义稳定 ID 排列的初始位置，不使用源研究局部布局抢占。从研究创建视图时明确复制该研究已保存的位置作为初始展示。
- 保存的折叠 ID 检查引用存在；拓扑资格在投影时再验证。成员变化只清理失去引用的位置和失效折叠，可整步撤销；外部改动引起的无效折叠须明确确认展开修复后才写视图，不自动丢弃。

路径输出包含原始方向、符号、条件、来源与 `truncated`。它查询有限简单路径，不用于闭环动态求解；截断或没有结果均不能推出实际游戏中无关联。

## 当前 I/O 与保存合同

CLI 提供 `init/serve/validate/root/migrate` 与帮助、版本。所有 API 需要本机会话 Bearer token，写入另外要求精确同源 Origin 与 `application/json`。静态资源采用精确白名单，不开放目录列表。

| 接口 | 请求与结果 |
| --- | --- |
| `GET /api/workspace` | 返回完整已校验工作区、`workspaceRoot`、`files: [{kind,id?,path}]`、`directories` 和整体 `revision`；路径映射仅存在于内存 |
| `POST /api/save` | `{ revision, kind, id?, document }`；analysis/view 按 `(kind,id)` 查当前文件；workspace 仅允许改名称、compositions 和 lastView |
| `POST /api/analyses` | `{ revision, document, file? }`；默认 `analyses/<id>.analysis.json`，可显式指定根内相对文件路径；完整创建后直接被发现 |
| `POST /api/views` | `{ revision, document, file }`；必须显式提供根内相对 `.view.json` 路径，不额外登记清单 |

保存成功返回回读后的完整工作区及新 revision。授权缺失 401，非同源 403，不支持操作 405，版本冲突/同名文件冲突 409，请求超过 3 MiB 返回 413，合同无效 422，提交结果待确认或新建部分完成 500。文件内容仍受 2 MiB 限制。

整体 `revision` 对配置、定义、全部分析图和视图文件的路径与原始 UTF-8 内容按路径排序取 SHA-256，并包含普通目录集合；格式修改、文件新增/移动/删除及空目录变化都会改变版本戳。页面自动保存视图同样经过 revision 校验。视图自动保存与规则保存共享串行队列，每次捕获明确目标与快照；失败暂停后续自动写入，保留草稿供导出，显式重新读取确认后才恢复，不自动采用新版本重试。

保存带读取时的整体 revision，在单工作区队列内重新读取和验证引用后写入。未知版本、断引用、过期版本或写入失败均不能当成功。已有文件用同目录临时文件替换，新建通过硬链接发布完整临时文件并原子拒绝同名目标，不再同时写清单。不支持该文件系统操作时明确失败。创建父目录后失败可能留下空目录；提交后回读失败需确认磁盘状态。详见[架构设计](架构设计.md)和[编辑器使用说明](编辑器使用说明.md)。

禁止把假设模型自动标记为实际规则。机制覆盖、结构比较与 agent 查询合同仍在讨论，见[模型优化讨论](模型对agent的价值与优化讨论.md)。实时战斗状态和行动规划不属于当前模型。
