# Game-Graph 文件协议：工作区 v4、机制与定义 v1、视图 v2

UTF-8 JSON 已由用户在 2026-08-31 确认。结构的唯一机器合同是 [`schemas/protocol.schema.json`](../schemas/protocol.schema.json)。正式合同只包含工作区 v4、机制与定义 v1、视图 v2；不包含 view v1、旧名称、旧 Schema 或运行时迁移协议。

## 四类文档

| 文档 | 必填内容 | 唯一归属 |
| --- | --- | --- |
| `workspace.json` | `schemaVersion: 4`、`kind: "workspace"`、`id`、`name`、`definitions`、`compositions` | 工作区身份、唯一定义入口、历史组合与最近打开记录 |
| `definitions.graph.json` | `schemaVersion: 1`、`kind: "definitions"`、`workspaceId`、`nodes`、`positions` | 统一概念与默认布局 |
| `mechanics/*.mechanic.json` | `schemaVersion: 1`、`kind: "mechanic"`、`workspaceId`、`id`、`name`、`scope`、`nodeIds`、`edges`、`positions` | 某张机制图的关系、范围和局部布局 |
| 任意普通目录的 `*.view.json` | `schemaVersion: 2`、`kind: "view"`、`workspaceId`、`id`、`name`、`mechanicRegistrations`、`collapsedNodeIds`、`positions` | 子机制注册、显隐与组合布局，不拥有规则 |

所有路径相对于工作区根。递归发现普通 `*.mechanic.json` 和 `*.view.json`，可在同一目录混放；排除隐藏条目和 node_modules，不持久化第二份清单。两类 ID 分别唯一，允许机制图与视图同 ID，路径映射按 `(kind,id)` 查找。支持中文路径，拒绝路径穿越、绝对路径、非法文件名、符号链接/junction 和嵌套工作区。未知版本、未知字段、坏文件、重复 ID、非法符号都整体拒绝。发现时点与迁移见 [CLI 与工作区](CLI与工作区.md)。

## 统一节点定义图

```json
{
  "id": "player-health",
  "label": "我方血量",
  "description": "当前分析主体的剩余血量，不指敌人血量。",
  "increaseMeaning": "剩余血量增加。",
  "tags": ["资源"]
}
```

`id` 在工作区内唯一，使用小写英文字母开头及英文字母、数字、点、横线或下划线，长度不超过 96。显示名可改；ID 不随名称改变。不同游戏默认拥有独立的定义图。`description` 说明抽象含义与粒度；`increaseMeaning` 给正负连线提供方向基准，不能空白。共享概念用于接合规则，不要求为每个敌人实例复制近战节点。

`positions` 是 `{ "节点ID": { "x": 40, "y": 80 } }`。机制图只保存自身节点位置；视图的 `positions` 是独立布局记忆，可保留当前隐藏但仍存在于统一定义中的节点坐标。Visible 只改变显示投影，不删除或用子机制局部坐标覆盖视图坐标；再次显示时恢复原位。首次出现且尚无视图坐标的节点会寻找不与已有布局重叠的位置。定义图不拥有因果边；总览可将机制图的边投影在这些节点之间并显示来源。

## 机制图与关系

```json
{
  "id": "damage-reduces-health",
  "source": "enemy-damage",
  "target": "player-health",
  "relation": "influence",
  "sign": -1,
  "condition": "伤害已经命中且未被吸收。",
  "note": "这是敌人对我方造成的伤害，而不是敌人受到的伤害。"
}
```

节点必须先定义，再在机制图 `nodeIds` 中引用；边端点必须属于该图的 `nodeIds`。边 ID 只在所属图内唯一；完整来源键是 `(graphId, edgeId)`。`scope` 写明图的规则范围、颗粒度、假设和未覆盖范围。`condition` 与 `note` 必须存在，可以为空，作为机制说明；条件不是当前战局的可执行状态，不需要判定某局体力或时序才能查询抽象抑制关系。本协议不承担 AND、资源守恒、阈值、时序或概率计算。

`sign: 1` 表示促进，`sign: -1` 表示抑制。消耗应表达为行动对资源的负向作用；资源支持行动可以是另一条正向关系，两者不是同一种输入。

## 影响与包含关系

每条作用边使用 `relation: "influence"` 并携带 `sign: 1/-1`；包含边使用 `relation: "contains"`，禁止携带 sign。例如：

```json
{ "id": "backstep-to-play", "source": "backstep", "target": "play", "relation": "contains", "condition": "", "note": "后撤步作为具体出牌行为，沿箭头影响出牌概念；不反向传播" }
```

黄色等号仅沿 source → target 单向传递宏观影响，可以位于路径开头、中间或末尾，不改变正负号。不建模“禁止”或具体效果。所有关系均按箭头方向传播，相反方向需独立连线，不自动抵消。source/target 明确决定方向。纯等号链返回 `kind: "containment"`，没有 sign；有正负边的路径返回 `kind: "influence"` 和相乘后的 sign。查询使用未折叠原图，不写回派生边，不证明数值相同或实时生效。

包含允许显式闭环与多条独立来源，只拒绝连接自身。简单路径不重复访问节点，并设数量、深度、展开量上限；截断明确标记，不迭代累计效果。机制、视图、追踪与下游筛选使用同一单向规则，未选机制不参与计算。

右键框选与多选只在页面存在，不进入协议。群组移动一次提交完整 positions：机制手动保存、视图自动保存；共同位移限制在坐标边界内，不能逐个裁剪破坏队形。取消手势不写入。包含相邻节点不能折叠；已有视图的折叠因包含边失效时仍走显式展开修复。

## 视图、最近打开与折叠

已有命名组合存于 `workspace.json` 的 `compositions`，包含 `id`、`name`、`graphIds`、`collapsedNodeIds`、`positions`。它只保存观察选择和布局，不复制节点或原始边。0.2.1 移除命名组合的界面入口，保留字段、原有内容和校验；不需要迁移文件。

独立视图示例（文件名、目录与 ID 相互独立）：

```json
{
  "schemaVersion": 2,
  "kind": "view",
  "workspaceId": "sample-card-game",
  "id": "melee-response",
  "name": "近战反制",
  "mechanicRegistrations": [
    { "mechanicId": "basic-rules", "visible": true },
    { "mechanicId": "encounter", "visible": true },
    { "mechanicId": "hand", "visible": false }
  ],
  "collapsedNodeIds": [],
  "positions": {}
}
```

`mechanicRegistrations` 是有序注册表，每项必须显式提供 `mechanicId` 和布尔 `visible`；同一机制不能重复注册，也不能注册视图。隐藏项仍属于视图，但不参与网页画布或 Agent 的当前关系、路径和影响范围。折叠 ID 必须属于某个已注册机制的节点；暂时隐藏导致折叠不可用时保留记忆，再次显示后重新判定。位置 ID 可以属于统一定义中的暂时隐藏节点。未打开的视图也参与全工作区校验，缺失来源不能部分加载。

可选 `workspace.lastView` 有两种互斥形式：内联状态与 `{ "viewId": "melee-response" }`，命名引用不能附带第二份勾选快照。0.4.0 打开机制只记录 `{ "graphIds": ["hand"], "activeLayerId": "hand", "collapsedNodeIds": [], "positions": {} }`；旧多图或带展示状态的内联记录只读预览，须明确保存为视图或放弃，不在启动时改写。无记录首次打开第一张机制。打开视图总是读取最新源图，重复点击也重新读取；候选验证成功后才替换画面。顶部概念表/机制图切换保留上下文，不写最近记录。

机制只看和编辑自身；命名视图在自身条目下展示已注册的子机制。视图旁的添加按钮注册子机制并默认 Visible，Visible 按钮只切换显示。注册表、组合位置和折叠自动写回 `.view.json`，源规则只读。「新建视图」从空注册表开始，也可从当前机制创建或将视图另存为。点机制离开视图不改原视图；返回视图重新读取源规则。创建文件与写最近记录是两次独立提交，后一步失败明确报告已创建路径，不重复创建或删除文件。

- 按稳定 ID 接合节点；同名异 ID 不自动合并。
- 同一图重复选择只算一次；图顺序不决定覆盖权。
- 不同图的同向或异向边都保留，来源可展开；不把异号边算成零。
- `visible: true` 的注册项组成当前模型范围，不等于当前回合已经激活的行动集合。
- 折叠在完整选图结果上执行。单入单出且不在有向环中的节点才允许折叠；摘要保留全部原始边与中间节点，重建未折叠投影即可展开。无效折叠请求报错。
- 机制位置优先于共享默认布局；视图使用自己的 `positions`，并保留隐藏节点的布局记忆。没有位置时用共享默认布局或按定义稳定 ID 寻找非重叠初始位置，不使用源机制局部布局抢占。从机制创建视图时明确复制该机制已保存的位置作为初始展示。
- 保存的折叠 ID 检查引用存在；拓扑资格在投影时再验证。成员变化保留节点位置记忆，只清理失效折叠，可整步撤销；外部改动引起的无效折叠须明确确认展开修复后才写视图，不自动丢弃。

路径输出包含原始方向、符号、条件、来源与 `truncated`。它查询有限简单路径，不用于闭环动态求解；截断或没有结果均不能推出实际游戏中无关联。

## 当前 I/O 与保存合同

工具偏好不属于游戏文件协议：`GET/POST /api/preferences` 读写固定用户配置目录下的 `game-graph/preferences.json`，只接受 `{version:1,snapToGrid:boolean}`。沿用会话与同源门禁，不接受任意路径，不改变工作区 revision；原子替换并回读，坏文件或链接路径明确拒绝。不同服务共享本机偏好，单布尔值采用最后确认写入；页面重新获得焦点时同步，不以浏览器缓存保存。

CLI 提供 `init/serve/validate/root` 与 `agent scopes/search/graph/node/impact`、帮助和版本。Agent 输出不改变文件协议，见 [Agent 查询接口](Agent查询接口.md)。所有 API 需要本机会话 Bearer token，写入另外要求精确同源 Origin 与 `application/json`。静态资源采用精确白名单，不开放目录列表。

| 接口 | 请求与结果 |
| --- | --- |
| `GET /api/workspace` | 返回完整已校验工作区、`workspaceRoot`、`files: [{kind,id?,path}]`、`directories` 和整体 `revision`；路径映射仅存在于内存 |
| `GET /api/agent` | command=scopes/graph/node/impact；带版本、来源和完整性的只读语义输出，读取与保存共享队列 |
| `POST /api/save` | `{ revision, kind, id?, document }`；mechanic/view 按 `(kind,id)` 查当前文件；workspace 仅允许改名称、compositions 和 lastView |
| `POST /api/mechanics` | `{ revision, document, file? }`；默认 `mechanics/<id>.mechanic.json`，可显式指定根内相对文件路径；完整创建后直接被发现 |
| `POST /api/views` | `{ revision, document, file }`；必须显式提供根内相对 `.view.json` 路径，不额外登记清单 |

保存成功返回回读后的完整工作区及新 revision。授权缺失 401，非同源 403，不支持操作 405，版本冲突/同名文件冲突 409，请求超过 3 MiB 返回 413，合同无效 422，提交结果待确认或新建部分完成 500。文件内容仍受 2 MiB 限制。

整体 `revision` 对配置、定义、全部机制图和视图文件的路径与原始 UTF-8 内容按路径排序取 SHA-256，并包含普通目录集合；格式修改、文件新增/移动/删除及空目录变化都会改变版本戳。页面自动保存视图同样经过 revision 校验。视图自动保存与规则保存共享串行队列，每次捕获明确目标与快照；失败暂停后续自动写入，保留草稿供导出，显式重新读取确认后才恢复，不自动采用新版本重试。

保存带读取时的整体 revision，在单工作区队列内重新读取和验证引用后写入。未知版本、断引用、过期版本或写入失败均不能当成功。已有文件用同目录临时文件替换，新建通过硬链接发布完整临时文件并原子拒绝同名目标，不再同时写清单。不支持该文件系统操作时明确失败。创建父目录后失败可能留下空目录；提交后回读失败需确认磁盘状态。详见[架构设计](架构设计.md)和[编辑器使用说明](编辑器使用说明.md)。

禁止把假设模型自动标记为实际规则。机制覆盖、结构比较与 agent 查询合同仍在讨论，见[模型优化讨论](模型对agent的价值与优化讨论.md)。实时战斗状态和行动规划不属于当前模型。
