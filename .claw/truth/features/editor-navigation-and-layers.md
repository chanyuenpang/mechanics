## 当前行为

- 顶部只有「概念表｜分析图」两种工作视图。侧栏按磁盘目录混排分析图和视图文件，提供「新建分析图」「保存为视图」；workspace.json、统一定义文件和旧命名组合不作为导航项。视图行没有勾选框，不是第二套虚拟分类。
- 「新增概念」创建共享定义草稿行，「引用概念」将稳定 ID 加入当前图的 nodeIds，「新建分析图」创建独立 JSON 文件。空工作区可以先建概念，再建首张图并引用。
- 概念表借鉴 SJE Array 的紧凑表格样式，不依赖 SJE。名称、含义、增加方向可行内编辑，三项必填；稳定 ID 自动生成且只读。引用检查覆盖所有持久化图，被引用概念不能删除。
- 顶部工作视图与记住的分析层分别管理。概念表草稿归定义文件；分析图草稿归当前分析文件。不能根据保留的 activeId 推断定义保存目标。
- 进入概念表保留原分析层、可见层、折叠和布局；返回分析图继续原范围。纯切换和定义文案编辑不写 lastView、不清空折叠。行内「查看引用」跳到所属图并定位节点，必要时主动展开该节点。
- 勾选决定叠加范围，点击文件决定编辑层；其他层内容只能浏览。隐藏编辑层会选择其他可见层，无可见层时没有当前编辑文件。最近视图保存的是图 ID，不保存合并副本。
- 页面只有一份当前文件草稿与撤销历史。跨文件/工作视图切换前提供保存、放弃、取消；规则手动保存，叠加选择自动保存。刷新重新读取最新源图；相机和顶部视图不持久化。
- 0.2.1 只移除历史组合的界面入口，保留 compositions 协议、原记录和校验，不迁移或删除用户数据。
- 0.3.0 新增真实 `.view.json`，打开后自动写回勾选、编辑层和折叠，规则仍手动保存。临时浏览内联 lastView 与命名引用互斥，协议升级 v3。新视图创建和记录最近打开是两次提交；后一步失败必须报告已创建路径，不重复创建或自动删除。
- 打开视图始终重新读取完整源文件，验证候选投影和折叠后才替换当前 UI。选择放弃草稿后若目标打开失败，原草稿仍保留。写入串行捕获目标与快照，自动保存失败暂停后续自动写入，规则和视图状态分别显示；视图与规则草稿分别导出，显式重读后恢复。

## 已验证与限制

2026-08-31 在两个隔离浏览器工作区验证：全局导航、侧栏精简、勾选/编辑分离、概念表往返、取消保留草稿、保存后返回、定义改名、引用跳转与展开、隐藏所有层、刷新恢复，以及空目录新增概念→中文嵌套目录首张图→引用→保存→重开。

概念表往返及定义文案草稿未改变 workspace.json 的 SHA-256；保存定义后，三份原分析文件字节不变，历史 compositions 与原示例一致。测试未打开或修改用户的正式工作区页面。`npm run check` 的 25 项测试与宿主显式 game-rule-analysis 域通过，但不等同于触屏、大规模图性能或全平台浏览器验收。

0.3.0 在独立临时工作区验证：创建视图、自动写回勾选/编辑层/折叠及重开恢复；源图外部改名后读取最新内容；版本冲突暂停、取消重读保留选择；缺失来源时放弃操作不销毁规则草稿；另存视图保留规则草稿、手动保存、退出及视图切换。自动保存阶段源分析 SHA-256 未改变。未对用户正式服务进行 QA 操作。

实现入口：`src/web/app.mjs`、`view-files.mjs`、`glossary.mjs`、`canvas.mjs`；操作说明见 `docs/编辑器使用说明.md`。
