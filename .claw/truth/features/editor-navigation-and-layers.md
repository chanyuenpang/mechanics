- 「引用概念」窗口支持搜索和直接新建：单个「创建并引用」，批量「加入待选并继续」，混合已有概念最后一次提交。名称从搜索词带入，名称与概念定义必填，自动生成稳定 ID；已有引用可见但不可重复勾选，同名需复用或明确另建，不按名称合并。概念表仍负责已有定义维护，也可先建定义再引用。
- 引用会话候选只在窗口内存；提交前取消不写任何文件，不修改机制草稿。提交预检引用与布局，再通过既有队列保存共享定义，最后一次 edit 加入原机制草稿，机制仍手动保存；不清空原草稿和历史，不跨文件撤销已保存概念。仅引用已有概念不写定义。
- ReferenceCommit 的失败或结果待确认禁止盲目重建；用户显式核实后，候选 ID 与内容全部已存在则只继续引用，全部不存在则等待明确重试；源机制改变、部分写入或 ID 内容不同均拒绝自动合并。已保存未应用可只重试引用。关闭失败窗口保留会话，切换前需处理或明确结束；结束不删除落盘定义，提供输入与机制草稿导出。
- 新引用位置围绕当前相机中心寻找空位，只写当前机制；页面按文件记忆已显示的隐式位置，避免共享定义排序变化挪动旧节点。引用后选中新节点，不强制适应画布；大批量可能延伸到当前画面外。视图无创建或引用入口，仍需进入源机制。
- 概念表借鉴 SJE Array 的紧凑表格样式，不依赖 SJE。名称、概念定义、aliases 与 tags 可编辑，名称和定义必填；稳定 ID 自动生成且只读。每行提供用户控制的 Agent 锁，锁只阻止 Agent mutation 的概念修改/删除，不阻止规则引用。引用检查覆盖所有持久化图，被引用概念不能删除。
- 顶部工作视图与记住的机制层分别管理。概念表草稿归定义文件；机制图草稿归当前机制文件。不能根据保留的 activeId 推断定义保存目标。
- 进入概念表保留原机制层、可见层、折叠和布局；返回机制图继续原范围。纯切换和定义文案编辑不写 lastView、不清空折叠。行内「查看引用」跳到所属图并定位节点，必要时主动展开该节点。
- 点击机制只打开自身关系，规则和局部位置手动保存；机制模式没有勾选。只有打开视图才能勾选机制，视图只拥有成员、组合位置、折叠并自动保存，源规则只读。点击机制退出视图不改变原视图成员。
- 「编辑源机制」进入单图，随后「返回视图」读取最新来源并恢复视图位置和本页相机。机制拖动只改机制，视图拖动只改视图；新节点确定摆放，不抢占已有位置。勾选变化只清理失去引用的位置与失效折叠，整步可撤销。
- 概念详情对有直接 is-a 父概念的子概念提供「显示连线」开关（当前父概念已显示在上方选择器里，开关不重复输出文字）：按当前文件把该概念加入或移出 `taxonomyPresentation.expandedNodeIds`，机制图写草稿、视图写视图文件并自动保存；切换立即重算显示投影，撤销/重做与重开恢复同一状态。收起后仅由 is-a 引入、没有焦点或影响边理由的父概念退出显示，落在投影外的节点或边选择同时被清理。
- 详情栏与「新建/修改概念」对话框的「is-a 父概念」都用仓库既有的可检索组合框（`ConceptReferencePicker`，`kind: 'isa'`）而不是 `<select>`，引用窗口里新建概念走同一条路径：候选排除自身与更具体的后代，当前父概念留在候选里并显示为已选中。检索输入名称、稳定 ID、别名即可过滤，两个字符以上才覆盖含义与标签，结果按完全相同 > 前缀命中 > 其它命中排序，身份命中始终排在只命中长文本的概念之前；列表每项只显示名称与稳定 ID，描述只留在悬停提示。打开下拉时输入框保留当前值的展示文字（名称（ID））并全选，过滤词与输入框文字分离；有当前值时候选首项就是「清除 is-a 父概念」，点它即清除，不做二次确认。
- 新建/修改概念对话框宽度取 `min(1040px, calc(100vw - 64px))`、`max-height: 92dvh`（`src/web/style.css` 的 `.concept-dialog`），窄视口由 `calc` 兜底且不出现横向溢出。字段按内容整行分组：身份分组整行（名称与稳定 ID 并排、概念含义整行）、is-a 分组整行、修改权限整行，检索信息与自定义文本并排；`.concept-editor` 的两列网格与这些整行规则是当前布局合同。
- 嵌在这两个对话框里的共享 `ConceptEditor` 以 `showActions: false` 构造（`src/web/glossary.mjs` 的构造参数），由编辑器自己渲染的动作行不再出现，保存/取消只由对话框底部一排按钮负责；对话框内容上的首次输入事件即把编辑标记为未保存（`conceptEditDirty`），关闭或切换文件前的确认仍然有效。`tests/project-open-ui.test.mjs` 固定对话框宽度与高度，`tests/concept-editor-entry.test.mjs` 固定 `showActions` 默认值与两处 `showActions: false`。

- 0.2.1 只移除历史组合的界面入口，保留 compositions 协议、原记录和校验，不迁移或删除用户数据。
- 0.3.0 新增真实 `.view.json`；0.4.0 分离机制/视图模式，替代原同屏编辑层交互。命名 lastView 只存 `{viewId}`，机制保存单成员内联最近记录，不保存临时折叠和相机。新视图从空集合开始，也可从机制创建。创建与最近记录两次提交；后一步失败须报告已创建路径，不重建或自动删除。
- 旧多图或带展示状态的内联记录启动只读保留，须明确保存为视图或放弃；无记录只打开第一张机制。正式协议为工作区 v13、definitions v7、rules v1、mechanic v8、view v5。
- 外部规则使保存的折叠失效，须明确确认展开修复才写视图；坏文件或断引用仍整体拒绝。机制删除可能破坏视图位置/折叠引用时先列出受影响文件，不自动联动清理。
- 打开视图始终重新读取完整源文件，验证候选投影和折叠后才替换当前 UI。选择放弃草稿后若目标打开失败，原草稿仍保留。写入串行捕获目标与快照，自动保存失败暂停后续自动写入，规则和视图状态分别显示；视图与规则草稿分别导出，显式重读后恢复。
- Agent 机制图草稿由服务会话托管，日常编辑唯一入口是 `agent draft open` → 编辑草稿文件 → `agent draft save`。再次 `draft open` 属于切换动作：服务先用与显式 save 相同的校验、排版、原子提交和文档导出事务保存当前草稿；保存失败时拒绝创建或切换目标，并保留旧草稿供核实。`draft open` 开始时清理统一临时目录中最后修改时间超过 24 小时的遗留草稿；清理、读取、校验、版本冲突、排版或导出失败都必须显式返回，不能用创建新草稿掩盖失败。
- 该协议的实现锚点为 `src/server/agent-draft.mjs`（过期清理、草稿文件读写与移除）和 `src/server/project-manager.mjs`（open 先 save、save 成功后移除）；`tests/agent-mutation.test.mjs` 覆盖保存后切换、保存失败保留旧草稿和超过 24 小时清理三条边界。成功 `draft save` 后草稿目录删除；失败路径不得声称 canonical 已提交。

## 演进历史

<!-- dated: 2026-09-01 -->
### 显式打开文件后的节点居中

机制图与视图文件每次显式打开完成后，都会对当前可见节点执行一次适应并居中；再次点击当前机制也会重新定位。空图不触发相机变更，节点坐标和保存状态保持不变。实测“后撤步规则”和“战斗1”视图的中心偏差均为 `0px / 0px`，完整测试 `120/120` 通过。

<!-- dated: 2026-09-23 -->
### 清除 is-a 不再让焦点节点从画布消失

显式投影（`ruleSelection: "explicit"`）下，只在 `focusNodeIds` 里、清除 is-a 后一条规则都没有的概念曾被当作孤点丢弃：无头 Edge 抓到的内部状态是 `draftFocus`/retained 仍有该概念，`graphNodes`/`displayNodes` 已无，定位到 `projectEndpointQualifiers` 把「不出现在任何边上」当作隐藏条件。修复后只有被限定投影接管的基础实例才隐藏，其余无规则成员保留；无头端到端确认清除后节点仍在、标签消失，`npm run check` 516 用例 / 514 通过 / 0 失败 / 2 个既有跳过。
