# ADR：独立视图文件自动写回，最近打开只记录引用

后续决策：0.4.0 的机制/视图编辑归属见 [双模式交互](2026-08-31-mechanic-view-modes.md)。本决策中的视图内编辑层和临时叠加入口已被替代；自动写回、独立文件与最近打开唯一引用继续成立。

## 背景

用户希望同一目录下可以保存、打开多套机制图叠加选择。0.2.1 的最近视图只有一份内联状态，旧 compositions 又不是文件树里的独立文件。2026-08-31 用户明确选择“自动写回”，而规则草稿仍手动保存。

## 决策

- 增加 `kind: view` 的 `.view.json`，只拥有机制图 ID、编辑层、折叠和观察位置，不复制规则，不嵌套视图。与机制图在真实目录中混排，按 `(kind,id)` 定位。
- 命名视图修改自动写回文件；manifest 的 lastView 仅存 `{viewId}`。未命名浏览才保存内联状态，两种形式互斥，避免同一选择有两个事实来源。
- 工作区升级 v3，视图文档使用 v1。旧 v1/v2 显式备份迁移，保留历史 compositions 和内联 lastView，不自动转换或同步旧组合。
- 打开视图读取最新完整工作区，在候选上验证叠加和折叠后替换画面。目标失败不销毁原草稿，不静默隐藏缺失层。
- 规则和视图共享串行写入队列，捕获明确目标与快照。视图保存失败暂停后续自动写入并允许导出；重新读取确认前不采用外部新 revision 重试。
- 创建视图和记录最近打开为两个单文件提交。后一提交失败报告已创建路径，不将部分完成伪装成原子回滚，不重复创建。

## 取舍与影响

不采用只存浏览器缓存、继续扩充 compositions 或同时保存引用与勾选快照，避免文件树与持久化对象不一致。保留完整工作区 revision，意味着其他标签页保存视图也会产生冲突；当前优先保护设计资料，暂不引入多文件事务、自动合并和多人协作。

规则编辑和视图自动写回必须有独立状态。文件读取/迁移的严格门禁涵盖未打开视图，因此外部删除源图会阻止整个工作区读写；错误要指向文件与引用，不能假装剩余图已完整加载。

## 验证

`tests/views.test.mjs` 与 `tests/view-opening.test.mjs` 覆盖文件/HTTP 边界、同 ID 分区、移动、原字节保护、显式迁移、候选打开、两次提交部分完成、响应丢失、串行快照和失败暂停。隔离浏览器验证自动写回、重开、冲突及草稿保留；这些不等于掉电、全平台或多人并发验证。
