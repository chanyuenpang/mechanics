# ADR：工具源码、游戏资料与开发知识独立归属

## 背景

规则分析工具起源于 Tiny World，但用户要求能分析其他游戏，并保留游戏项目内的 JSON 资料。仅拆出源码仓库仍不足以实现独立维护：早期任务与 Truth 落在宿主，后续 CLI 和编辑器演进未完整反映到工具自己的知识入口。用户于 2026-08-31 明确要求初始化工具独立 claw-kit。

## 决策

- 通用源码、Schema、示例、设计文档和 Truth/ADR 归工具独立仓库；宿主可通过 Git 子模块固定已推送的工具提交。
- 每个游戏拥有自己的分析工作区，包含配置、统一概念定义和机制图；不放进工具安装目录，不将宿主规则编译进工具。
- 工具仓库单独初始化 `.claw/project.json`，启用 planning、memory 与 docs 检索，知识任务采用 Codex subagent 执行方式。后续工具任务从工具根启动，不使用父项目作为默认知识落点。
- 本次已经在宿主运行的导航任务在原计划收尾，不复制活动任务。新建或拆分独立项目时先确认工作流和知识归属，不能把独立 Git 仓库等同于独立 claw 项目。
- 共享配置与 Truth/ADR 随工具提交；个人覆盖、任务、索引、会话与运行态忽略。宿主只保留接入、数据落点和版本更新规则，通过链接引用通用合同。
- claw-kit 是开发工作流，不是工具运行依赖；不要求使用者先初始化 claw 才能分析游戏。

## 其他方案

- 所有知识放宿主：启动方便，但工具离开宿主后丢失决策与操作上下文，维护边界不完整。
- 把宿主与工具的 Truth 全部复制两份：会出现两个当前事实来源，后续容易漂移。
- 将游戏数据放进工具仓库：安装和示例简单，但违背游戏资料归属及跨游戏复用要求。

## 影响

工具开发须在独立根完成知识检索与收尾；跨仓库修改明确区分工具事实和宿主事实。初始化与索引通过不等于自动沉淀已执行，只有实际 Truth/ADR 和收尾结果可作为证据。能力变更须在实际验收后才记录为已验证行为。
