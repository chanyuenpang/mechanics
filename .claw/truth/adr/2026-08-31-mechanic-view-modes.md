# ADR：机制单图编辑，视图只编辑组合与展示

## 背景

0.3.0 点击机制会改变编辑层，却保留勾选集合；位置又优先来自编辑层，造成相同勾选下画面跳变。用户明确要求点机制只看自身，只有打开视图才可勾选；在查看架构推荐后回复「实施」。

## 决策

- 采用推荐 A：机制单文件编辑、手动保存；视图只改成员、位置、折叠并自动保存，源规则只读。
- 「编辑源机制」进入单图，随后「返回视图」重读最新来源并恢复视图布局与本页相机。不设置视图内的编辑层选择器。
- 目录名称始终是打开文件，勾选始终是修改视图成员。切换机制不改原视图；视图节点拖拽不改任何源机制字节。
- 视图已有位置优先，成员变化不全量清空位置或折叠，作为一个可撤销动作；机制与视图撤销保存边界分开。
- 每次显式打开机制图或视图文件完成加载后，若当前可见节点非空，按节点包围框将其中心定位到画布可视区域中心；该操作只改变会话相机，不改节点坐标、布局或保存内容，空图保持原相机。再次打开当前机制同样执行定位。
- 沿用协议。旧内联记录只读保留直到明确保存或放弃；旧命名视图按原 activeLayerId 内存物化位置，首次展示编辑写入完整位置并置空该字段，打开不自动改文件。
- 外部拓扑导致折叠失效时提供显式展开修复，失败保留原画面与草稿。保存失败沿用暂停/导出/重读，不自动重试。
- Agent 机制编辑沿用“机制手动保存”的边界，但由服务会话托管临时草稿：`agent draft open` 发生目标切换时，必须先用与 `draft save` 相同的校验、排版、原子提交和导出事务保存旧草稿；保存失败拒绝切换并保留旧草稿。open 同时清理超过 24 小时的遗留草稿，清理或保存失败均显式暴露，不以新草稿或默认值掩盖。

## 取舍与证据

编辑源规则暂时离开叠加画面，换取同屏只有一种可写文件语义。未采用 B 的同屏编辑层模式，也不增加多标签、嵌套视图或第二份规则真相。

`tests/view-opening.test.mjs` 真实文件测试验证位置接管、单图导航、源文件不变、成员反向保存和修复门禁；隔离浏览器实际验证勾选、拖动、撤销、单图编辑返回、相机保持、冲突与折叠修复。此次变化不需要工作区迁移。

Agent 草稿协议由 `src/server/agent-draft.mjs`、`src/server/project-manager.mjs` 实现，`tests/agent-mutation.test.mjs` 覆盖保存后切换、保存失败保留和过期清理；这些测试记录的是当前工具仓库的服务边界，不扩大为掉电恢复或多人并发承诺。

### 显式打开后的可见节点居中

确认打开机制图或视图后执行一次按当前可见节点包围框的适应与居中；空图不改相机，节点坐标与保存状态保持不变。浏览器实测两个代表性文件的中心偏差均为 `0px / 0px`，完整测试 `120/120` 通过。
