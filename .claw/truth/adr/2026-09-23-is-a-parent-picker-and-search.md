# ADR：is-a 父概念改用可检索选择器

## 背景

is-a（`specializes`）父概念原先由节点详情栏与「新建/修改概念」对话框里的 `<select>` 长下拉框维护。概念一多，长列表无法按名称定位；更严重的是候选集合沿 `specializes` 的**出边**计算，而这条关系的方向是「具体概念 → 父概念」，算出的其实**是祖先集合**：详情栏把当前父概念当成「后代」排除，`select.value` 匹配不到任何 option 就显示为空；同时真正的后代没有被排除，用户仍能选出必然成环的父概念。工具需要可检索的选择方式，并继续保证「每个概念至多一个 is-a 父概念、禁止自连接与成环」的既有不变量。

## 决策

- 后代语义的 owner 是 `src/domain/graph.mjs` 的 `specializesDescendants(rules, conceptId)`：只沿 `specializes` **入边**收集更具体的概念。祖先方向仍由 `src/domain/query-paths.mjs` 的分类透传沿出边上溯，两个方向不得混用。
- 父概念候选的 owner 是 `src/web/glossary.mjs` 的 `isaParentCandidates`：全部概念减去自身与 `specializesDescendants` 的返回值；**绝不排除祖先**。当前父概念必须留在候选里，否则控件无法显示已保存的值。
- 节点详情栏与「新建/修改概念」对话框的 is-a 字段都改用仓库既有的 `ConceptReferencePicker`（`kind: 'isa'`）可检索组合框，不再使用 `<select>`；引用窗口里新建概念复用同一条路径。详情栏的展开开关文案改为「显示连线」，当前父概念已显示在选择器里，开关不再重复输出文字。
- 检索沿用 `matchingConcepts` 的分级：一个字符只匹配名称、稳定 ID 与别名，两个字符以上才覆盖含义与标签；结果按完全相同 > 前缀命中 > 其它命中排序，身份命中始终排在只命中长文本的概念之前。列表每项只显示名称与稳定 ID，描述只留在悬停提示。
- 打开下拉时输入框保留当前值的展示文字（`名称（ID）`）并全选，过滤词与输入框文字分离（`query` 与 `input.value` 各自持有）；有当前值时候选列表第一项就是「清除 is-a 父概念」，点它即清除，不做二次确认。

## 取舍

- **保留 `<select>` 长下拉**：未采用。概念变多之后无法按名称、稳定 ID 或别名定位。
- **继续用出边遍历排除候选**：未采用。方向反了会得到祖先集合，正是「已有 is-a 父概念却显示为空、又能选出成环父概念」的根因。
- **把清除做成选择器外独立的「清除 is-a 父概念」按钮**：曾采用，未保留。它把「清除」和「更换为另一个父概念」拆成两个位置不同的动作。
- **清空输入后就地弹「清除 / 保留」二次确认**：曾采用，未保留。复核后确认清除应当是候选列表的第一项，点它即清除，不增加确认成本。
- **所有查询都覆盖描述与标签**：未采用。单字中文查询会因为某字在描述里出现一次，就把大量无关概念刷进列表。
- **列表显示描述预览**：未采用。预览看起来不像匹配结果；描述改为只出现在悬停提示。

## 影响

候选方向与清除语义必须继续同源：新增候选来源时要排除自身与真正的后代，新增选择器用法时要沿用 `isaParentCandidates` 或等价约束；检索分级应由 `matchingConcepts` 单点决定。回归覆盖 `specializesDescendants`（链式、只沿入边、影响规则不参与）、is-a 候选与检索（含「当前父概念必须在候选里」）、选择器结构与界面钩子。协议不变，仍为 workspace v13 / definitions v7 / rules v1 / mechanic v8 / view v5；本决策不新增字段，也不落盘派生数据。

证据锚点：`src/domain/graph.mjs`、`src/web/glossary.mjs`、`src/web/app.mjs`；`tests/concept-taxonomy.test.mjs`、`tests/concept-reference.test.mjs`、`tests/concept-editor-entry.test.mjs`、`tests/project-open-ui.test.mjs`。

### 清除交互的两次调整

可检索选择器落地后，清除先是选择器外的独立按钮；复核后改为清空输入、失焦或回车时就地弹「清除 / 保留」确认条；最后按要求回退为候选列表第一项，点它即清除、取消二次确认。保留这段是因为「清除」的位置与确认成本已经被推翻两次，后续再调整需要知道前两种方案为何被放弃。
