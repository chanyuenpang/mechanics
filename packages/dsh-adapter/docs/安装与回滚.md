# DSH × Mechanics 插件：安装、验证与回滚

面向本机 DSH（DeepSeek Harness）web profile 的可复制操作手册。包位于
`packages/dsh-adapter`，包名 `@veewo/dsh-mechanics`。

## 0. 前置条件：项目内受管工具必须是新版

插件不读 canonical、也不自带投影实现：它按 argv 直跑 **项目内** 的
`<项目>/.mechanics/tools/workspace-tool.mjs`。该工具必须支持
`search --query` 的模糊回退与 `graph --ids`，即 `guide` 的 `contractVersion >= 5`。

```powershell
node G:\Projects\tiny-world\.mechanics\tools\workspace-tool.mjs guide
```

若项目工具协议低于 5，先在已初始化的项目里运行 `mech sync --project <项目目录>`，不要手工覆盖受管文件。

版本不符时不会静默降级：`mechanics_graph` 会带着工具自己的 `TOOL_INVALID` 失败。

## 1. 安装（一条命令）

```powershell
dsh plugin --profile web add @veewo/dsh-mechanics@latest
```

- `dsh plugin` 把参数转发给 profile 目录里的 pnpm，并按**安装结果**自动把声明了
  `dsh.bundle` 的依赖并入 `dsh.profile.bundles`——不需要手工编辑 profile 的
  `package.json`。
- 发布包随其声明的 Mechanics 依赖一起安装；若用本仓绝对路径替代包名安装，则以 link 指向源码目录，源码更新仍要重启宿主。

## 2. 重启宿主

插件在宿主启动时组装，必须重启 `dsh web`（当前会话会中断）。

## 3. 重启前先跑预检（可选但推荐）

预检用 DSH 自己的校验函数把两半过一遍——客户端半的解析路径与 `dsh.client` 声明、host 半的
`register()` 契约（输出面、`timeoutMs`）、参数与输出 JSON Schema 是否属于受支持子集、
非法参数是否在派发前被拒、`render` 与 `presentationMeta` 是否产出预期形状。

它还会在**真实的 DSH 工具注册表**（cordis `Context` + `ToolRuntime`）里注册一次并**真的派发**
两个工具：对示例工作区跑一次检索与一次图投影，断言注册表可见的 schema 字段、模型可见文本，
以及随结果物化的卡片 `meta`。也就是说重启前就能验证到"注册表 → 参数校验 → 工具执行 →
内容与卡片载荷"整条链路，剩下的只有 HTTP 与浏览器渲染。重启一次很贵，先用它换掉一次白重启：

```powershell
node packages/dsh-adapter/scripts/preflight.mjs
```

退出码 0 且末尾打印 `预检通过：可以重启宿主` 即可。DSH 装在非默认位置时用
`--dsh-tools <…/dsh-tools/lib/index.js>` 或 `--dsh <…/@deepseek-ai/dsh>` 指定。

## 4. 重启后的验证

**a) 先跑脚本化验收**（重启后一条命令，只观测不改状态）：

```powershell
node packages/dsh-adapter/scripts/verify-host.mjs --token <网页登录令牌> --project <项目目录> --ids <概念ID,概念ID>
```

脚本从已认证的首页启动图提取真实的组合脚本 URL，核对批次包含 Mechanics 模块并返回 200；还会检查插件的只读路由和指定项目的图页面。当前 DSH 不再提供旧的单文件 `/plugins/@veewo/dsh-mechanics/client.js` 路由，那个 404 不代表插件未加载。最近会话日志有调用时另核对 PTC 完成事件；没有调用则跳过该项，不声称对话图卡通过。

**b) 工具进入会话**：新会话的工具清单里应出现 `mechanics_search` 与 `mechanics_graph`。

**c) 图卡进入对话流**：

1. 先让模型调 `mechanics_search { "query": "闪避" }`——精确未命中时应返回模糊候选。
2. 再用候选里的稳定 ID 调 `mechanics_graph { "conceptIds": ["<id>", "<id>"] }`。

对话流里必须出现独立的 `mechanics-widget` 图卡节点，可缩放、平移和悬停查看详情；`mechanics_graph` 执行成功与 `/mechanics/widget` 页面返回 200 不能代替这一项验收。

## 5. 回滚（一条命令 + 重启）

```powershell
dsh plugin --profile web remove @veewo/dsh-mechanics
```

- 重新组装会把它移出 `dsh.profile.bundles`；重启后 host 工具与两张卡一起消失。
- 项目侧零残留：插件不写 canonical、不新建文件、除注册工具与槽位外不留下状态。
- 需要连第 0 步一起回退时，把原来的 `workspace-tool.mjs` 换回项目即可（该文件由
  `mech` 管理，不在项目 git 里）。

## 6. 已知边界

- 插件经 DSH 的 subprocess seam 按 argv 直跑 `node`，**不经过** DSH 的文件沙箱：
  它以宿主权限读取项目 JSON。只在可信项目上启用。
- 一次最多 64 个概念，超出显式失败（`TOOL_INVALID`）。
- 客户端是手写模块；当前 DSH 为组合脚本生成自己的 source map，不能用旧单文件 map 路径的状态判断加载结果。
- 本轮**只读**：没有任何写入入口；草稿编辑通道见计划中的后续任务。
